# FJU IM Spec Writer(輔大資管 專題規格書生成 Skill)

🇬🇧 [English](README.en.md) | 🇹🇼 繁體中文

給 Claude 用的 Agent Skill,協助生成/修改輔仁大學資訊管理學系《系統分析與設計》課程的畢業專題規格書,依照老師規範的章節結構、格式與審查標準產出Word文件。

> **重要聲明**:這個工具是輔助排版與內容組織,**不會替你捏造專題內容**(如問卷數據、訪談結果、系統邏輯)。所有實質內容(需求分析、User Story細節、資料庫設計等)仍需要你自己提供或確認,skill只負責依照老師規範把內容組織成正確的格式,並在資訊不足時明確標記「待確認」。
>
> **關於`examples/`與`templates/`資料夾**:本地版skill包可能含有老師的官方範本docx,以及一份透過指導教授取得的歷屆優秀範例(真實學生的畢業專題)。這些檔案**不屬於本public repo的一部分**(見`.gitignore`),因為內容版權/隱私屬於原課程與原作團隊。若你clone這個repo,這兩個資料夾會是空的,不影響skill其他功能,但你需要自己準備這些檔案才能實際使用(見下方「開始使用前你需要準備的東西」)。

## 這個skill適合誰

- 輔仁大學資訊管理學系,正在修《系統分析與設計》課程或撰寫畢業專題規格書的學生
- 想參考這套「用skill生成規格文件」架構,自行套用到自己課程/老師規範的其他學生
- 想了解Claude Agent Skill實務設計案例的任何人

## 這個skill做什麼、不做什麼

**能做的**:

- 依老師規範的章節結構、格式(表格/文字段落判斷、User Story卡片格式、資料庫表格式等)組織你提供的內容
- 檢查前後章節有沒有邏輯矛盾(例如問題陳述提到的問題,系統範圍卻沒對應功能)
- 在深度訪談階段,依規範需要哪些欄位,一次性列出問題清單問你,提醒你有沒有漏想的面向
- 產出符合格式規範的正式Word文件(字型、字級、頁碼、目錄、圖表自動標號等)

**不做的**:

- **不會**替你發想「這個系統應該有哪些功能模組」
- **不會**替你編「你們的競品應該是誰、優缺點是什麼」
- **不會**替你決定「利害關係人的期望是什麼」

這些都需要你(或你們團隊)自己做功課(訪談、市場調查、技術評估),skill只負責把你的想法組織成正確格式。如果你想要「發想功能」這類創意協助,直接跟Claude對話即可,不需要透過這個skill——那是Claude本身的一般對話能力,跟這個skill是兩件事。

## 開始使用前你需要準備的東西

因為版權/隱私考量,這個public repo**不包含**下列檔案,你需要自己準備:

1. **老師的官方範本**:系統分析與設計課程中老師提供的教學範文,向授課教師索取,放進`templates/`資料夾
2. **(選用)歷屆優秀範例**:如果你有透過老師取得的歷屆範例文件(PDF或Word),放進`examples/`資料夾,能大幅提升skill生成內容的品質——skill會依範例文件的實際寫法分析出「老師沒寫在規範網頁上,但從範例品質差異能看出來的審核偏好」

**沒有範例文件一樣能用**,`reference/`資料夾裡已經有從既有範例萃取整理好的規則(`chapter_requirements.md`、`content_synthesis_guide.md`等),只是若你的老師換了新範本、規則有變動,建議依下方「規則可能過時,如何更新」的說明處理。

## 安裝方式(Claude.ai 網頁/App)

1. 打開Claude.ai,進入 **Settings → Capabilities**,確認「**Code execution and file creation**」已開啟
2. 進入 **Customize → Skills**
3. 點選「**+**」→「**+ Create skill**」
4. 把整個 `fju-im-spec-writer/` 資料夾**壓縮成ZIP**上傳。**注意壓縮方式**:ZIP裡面第一層要直接是`fju-im-spec-writer/`資料夾本身,不要多包一層外層資料夾,也不要把裡面檔案散裝直接壓縮
5. 上傳完成後,回到Skills清單,**確認這個skill的開關是打開的**(有些介面上傳完預設是關閉的)

免費、Pro、Max、Team、Enterprise方案皆可使用。個人上傳的custom skill僅自己帳號可見;Team/Enterprise方案可在Skills設定中分享給組員(但skill包本身的協作限制見下方「兩人以上協作」)。

## 第一次使用:完整流程走一遍

**你不需要手動「呼叫」這個skill。** 裝好並開啟後,直接跟Claude說你要做什麼,Claude會依你訊息裡的關鍵字(如「規格書」「User Story」「資料庫設計」)自動判斷該不該用它。

### 步驟一:開場,告訴Claude你要開始寫規格書

例如:「我要開始寫我們的畢業專題規格書,這是我們第一次用這個skill」。

### 步驟二:專案深度訪談(只做一次)

Claude會先進行一場完整的背景訪談,把整個專題的背景一次問清楚,包括:

- 專題名稱、核心概念、要解決的問題
- 利害關係人、需求蒐集方法、競品分析
- 功能模組概況、技術規劃
- 團隊成員與分工

回答完後,Claude會把這些整理成`state/project_context.md`(背景知識庫),**之後生成任何章節都會直接讀這份檔案,不會重複問你已經回答過的背景問題**。

### 步驟三:確認要用預設參考來源,還是自訂

Claude會問你:要套用skill內建的預設參考策略(依111/114範本與歷屆範例分析出的逐章節建議),還是你有不同的參考文件想指定。**這一步只問一次**,答案會記錄下來,之後不會每次重問。

### 步驟四:逐章節生成

跟Claude說要寫哪個章節(例如「幫我寫第一章的問題陳述」)。Claude會:

- 先確認這章節需要的細節資訊你是否都提供了,缺的會直接問
- 以小節為單位生成,每寫完一小節就對照規則自我檢查,過關才寫下一節
- 你可以隨時喊停修正,不用等一大段寫完才發現方向錯了

### 步驟五:彙整與輸出

所有需要的章節都確認過後,Claude會把它們組合成一份完整的Word文件(套用正確的字型、頁碼、目錄格式),輸出給你下載。

### 之後的修改

老師給了回饋,直接告訴Claude要改哪個章節,**不用整份重寫**,Claude會針對那個章節重新處理,並記錄回饋內容避免下次犯同樣問題。

## 兩人以上協作

**重要限制,務必先了解**:Claude.ai的custom skill是上傳到**個人帳號**的,`state/`底下的檔案只是skill包裡的靜態範本骨架。在對話中對這些檔案做的更新,**不會自動同步回你上傳的skill包,也不會同步到組員的skill包**。真正要達成「共用」,你們需要一個**skill之外的外部共用空間**存放「有實際內容」的`project_context.md`與`project_state.md`,例如:

- Google Drive共用資料夾(若有連接Google Drive,可直接讀寫該檔案)
- 你們專題本來就有的GitHub repo
- 或最簡單:誰更新了內容,就把最新版檔案傳給對方,下次對話開頭先貼給Claude

**實際協作流程**:

1. 決定共用位置
2. 任何一人先做過深度訪談,產生`project_context.md`後,存到共用位置
3. 另一人開始工作前,先把共用位置裡最新版的`project_context.md`跟`project_state.md`貼給Claude
4. 開始寫某章節前,先看進度表確認這章沒有人在寫,避免兩人同時生成同一章節
5. 寫完後記得把更新後的檔案存回共用位置,讓對方下次能看到最新狀態

## 規則可能過時,如何更新(給未來的學弟妹)

老師的規範會隨學期調整(例如111版→114版的改版),`reference/content_synthesis_guide.md`裡的分析是基於**目前這三份參考文件**(111範本、114範本、Beaton音樂祭平台範例)做的,**不是永久寫死的規則**。

如果你發現:

- 老師換了新範本
- 你手上有更新的歷屆優秀範例
- 老師規範網站的內容有更新

**建議做法**:把新的範本/範例文件提供給Claude,直接說「我想用新的參考文件重新分析`content_synthesis_guide.md`」,Claude會用同樣的分析方法(逐章節比對完整度、萃取寫作優點、找出隱性偏好)重新產出對應的分析內容,取代或補充現有的版本。skill在開始生成內容前也會主動問你要套用預設還是指定新來源(見SKILL.md「階段一」)。

## 常見問題

**Q:每次都要重新解釋一次專題背景嗎?**
不用,第一次深度訪談後會存成`project_context.md`,之後只要這份檔案還在(或你把它貼給Claude),就不用重講。

**Q:會不會有幻覺、亂編內容?**
skill設計上會主動問缺的資訊,不會自己編。但本質上仍是LLM,還是可能出現幻覺(如誤植A功能的細節到B功能),生成後建議自己核對重要數字與情境細節。

**Q:兩人各自上傳skill後,對方看得到我改的東西嗎?**
看不到,見上方「兩人以上協作」段落的說明。

**Q:一定要照skill的建議走嗎?**
不用,`content_synthesis_guide.md`裡的分析是**建議**,不是老師正式公告的規定。任何跟老師規範有出入的地方,skill都會明確標註提醒,正式繳交前建議再向老師或助教確認。
