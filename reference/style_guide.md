# 格式與範本規則

來源: 111/114 SA範本.docx + 老師規範網站 + 歷屆優秀範例

## 文件基本格式

- 輸出格式為 Word(.docx),需使用 docx skill 產生
- 封面需包含:專題名稱、成員學號姓名、指導教授、報告完成日期
- 需有「修改紀錄」表格(日期、變更說明、版本號),每次重大修改都要記錄
- 需有完整目錄(章節、頁碼)
- 圖片需依序編號並加標題(如「圖一:誠品首頁」),文中需明確引用圖號(如「如圖一所示」)
- 表格需依章節編號(如「表1-1」)

## 使用者故事卡格式(逐字對照範本)

### Epic卡片

```
| 名稱 | {Epic編號} {Epic名稱(動詞開頭)} | 類別 | Epic |
| --- | --- | --- | --- |
| 角色: 身為 {角色} 需求: 我想要可以 {需求} 價值: 因此我可以 {價值} 接受條件: {列點式,說明所包含user story間的關係} |
```

### User Story卡片(單一情境)

```
| 名稱 | {編號} {User Story名稱(動詞開頭)} | 類別 | User Story |
| --- | --- | --- | --- |
| 角色: 身為 {角色} 需求: 我想要可以 {需求} 價值: 因此我可以 {價值} 接受條件: Given {前置條件/前一個user story} When {使用者動作,含詳細輸入資料} Then {驗證結果,含詳細輸出資料} |
| 優先順序 | {1/2/3} |
```

### User Story卡片(多情境)

```
| 名稱 | {編號} {User Story名稱} | 類別 | User Story |
| --- | --- | --- | --- |
| 角色: 身為 {角色} 需求: 我想要可以 {需求} 價值: 因此我可以 {價值} 接受條件: Scenario 1:{情境名稱} Given {...} When {...} Then {...} Scenario 2:{情境名稱} Given {...} When {...} Then {...} |
| 優先順序 | {1/2/3} |
```

## 資料庫設計表格格式

**關連一覽表:**
```
| 編號 | 名稱 | 說明 |
| --- | --- | --- |
| 1 | Product | 產品 |
```

**關連結構(每個資料表各一張表):**
```
- {資料表名稱}

| 編號 | 名稱 | 型態 | 說明 |
| --- | --- | --- | --- |
| 1 | Id | BIGINT(11) | 編號 PK AI NN |
| 2 | CategoryId | INT(11) | 類別編號 FK (Category.Id) NN |
```

表後附註解:`PK:Primary Key`、`FK:Foreign Key`、`AI:Auto Increment`、`NN:Not Null`

## 介面藍圖格式

**介面藍圖一覽表:**
```
| 編號 | 名稱 | 對應使用者故事 |
| --- | --- | --- |
| 1.1 | {畫面名稱} | {對應的user story編號與名稱} |
```

**介面藍圖(逐個畫面):**
```
| {編號} {畫面名稱} |
| --- |
| {畫面截圖或線框圖} |
| 說明 {每個元件對應的動作、點擊後跳轉的介面編號} |
```

## 資源需求表格格式

```
| 經費項目 | 經費名稱 | 金額 | 說明 |
| --- | --- | --- | --- |
| 硬體需求 | {項目} | {金額} | {說明} |
| 軟體需求 | {項目} | 0 (Open Source) | {說明} |
| 人力需求 | {工時*人數*時薪} | {金額} | {說明} |
| 總計 | | {總金額} | |
```

分「開發階段」與「營運階段(前三年)」兩張表,格式相同。
